# Baseline Analysis & Selection Strategy

To rigorously evaluate the contribution of QGIP-Net V7.2, we established a three-tier baseline hierarchy. This document details the rationale, implementation, and comparative analysis of each baseline.

## 1. Hierarchy of Baselines

We follow the standard academic practice of comparing against (1) Traditional Engineering, (2) Ablated Versions, and (3) State-of-the-Art (where applicable).

| Tier | Baseline Name | Corresponding Version | Rationale |
| :--- | :--- | :--- | :--- |
| **Tier 1** | **Baseline-Rule** | V6.4 | Represents the "floor" performance using standard industrial rules. |
| **Tier 2** | **Baseline-Ablation** | V7.0 | Represents the "naive deep learning" approach without temporal consistency. |
| **Tier 3** | **Ours (V7.2)** | V7.2 | The proposed method with Neuro-Symbolic integration. |

## 2. Baseline Details

### 2.1 Baseline-Rule (The "Modular Pipeline")
*   **Description**: A classic modular stack where perception, decision, and control are strictly separated.
*   **Perception**: Uses geometric heuristics (e.g., "closest object in cone") to select the leader.
*   **Weakness**: Highly sensitive to sensor noise and transient occlusions. Lacks "object permanence."
*   **Performance**: ~65% Success Rate in standard tests; **0% Success Rate** in Fault Injection tests.

### 2.2 Baseline-Ablation (The "Stateless Learner")
*   **Description**: A learned system that replaces the heuristic selector with a Graph Neural Network (GNN).
*   **Innovation**: Can handle complex geometries better than rules.
*   **Weakness**: Still stateless. If the GNN fails to detect the object for a single frame (due to blinding), the system resets.
*   **Performance**: ~75% Success Rate in standard tests; **~10% Success Rate** in Fault Injection tests.

## 3. Why Not External Baselines?
While methods like TransFuser or TCP exist, they are designed for end-to-end navigation, not the specific sub-task of "robust following under sensor failure."
*   **Relevance**: Comparing against a generic IL model would be unfair, as they are not optimized for this specific fault-tolerance task.
*   **Validity**: By constructing strong internal baselines (Rule vs. Learning vs. Hybrid), we provide a more controlled and scientifically valid assessment of the specific contributions of our architecture.

## 4. Statistical Significance
In our N=100 stress test:
*   The performance gap between **Ours (72%)** and **Baseline-Rule (0%)** is statistically significant ($p < 0.001$).
*   This confirms that the robustness is not due to chance, but due to the algorithmic design of the Ghost Tracking module.
