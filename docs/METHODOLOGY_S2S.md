# 方法论：协议对齐的流式采集

本文档详细介绍了用于创建 **S2S (Snapshot-to-Sequence)** 数据集的数据采集方法。该方法旨在支持目标选择与轨迹预测的 **联合学习 (Joint Learning)**，专门解决几何模糊性和物体恒常性带来的挑战。

> **注意**: 本文档侧重于 *数据采集方法论*。关于 *控制系统方法论* (Neuro-Geometric MPC)，请参考 **[CONTROL_SYSTEM_V6.md](./CONTROL_SYSTEM_V6.md)**。关于全系统概览，请参见 **[FULL_SYSTEM_REPORT.md](./FULL_SYSTEM_REPORT.md)**。

## 1. 核心概念：协议对齐 (Protocol Alignment)

该数据集的核心创新在于 **协议对齐**。在传统的自动驾驶数据集中，“选择”（决策）和“执行”（轨迹）往往是解耦的，或者是在不同的过程中采集的。这导致了 **分布偏移 (Distribution Shift)**，即训练时用于选择的图特征与执行时遇到的动态环境不匹配。

**协议对齐** 确保了：
1.  **冻结几何 (Frozen Geometry)**: $t=0$ 时刻用于目标选择的几何状态 (协议图) 与轨迹回放的初始状态在数学上是完全一致的。
2.  **反事实一致性 (Counterfactual Consistency)**: 对于同一个几何场景，我们采集对应于不同高层指令 (Query) 的多条轨迹，允许模型学习 `Query -> Target -> Trajectory` 的因果链路，同时保持几何结构不变。

## 2. 数据采集流水线

采集过程遵循严格的 **O-E-A (Oracle-Expert-Audit)** 流水线，在 `scripts/data/collect_s2s_data.py` 中实现。

### 阶段 1：场景生成与协议冻结
*   **生成**: 我们在 Ego 车辆周围生成一个包含 $N=6$ 辆候选车辆的密集交通场景。
*   **协议图**: 在 $t=0$ 时刻，我们捕获静态场景图 $G = (V, E)$。该图包含：
    *   节点特征：位置、朝向、速度、车道 ID。
    *   边特征：相对距离、相对角度。
    *   **候选掩码**: 一个指示哪些节点是有效候选者的二进制掩码。
*   **冻结**: 该图状态被保存，并用作所有后续反事实分支的“锚点”。

### 阶段 2：反事实分支 (重置-回放)
对于每个场景，我们遍历一组指令 $Q = \{ \text{"same\_lane\_front"}, \text{"left\_lane\_front"}, \text{"right\_lane\_front"} \}$。

对于每个指令 $q_k \in Q$:
1.  **Oracle 选择**: 基于几何规则的 Oracle 确定 Ground Truth 目标 $v_{target}$。
    *   *规则*: 车道相邻性检查、前向向量对齐和最近邻逻辑。
2.  **重置-回放**: 模拟器状态重置到精确的 $t=0$。这至关重要。它保证了 Ego 车辆在所有指令下都从 *完全相同* 的几何条件出发。
3.  **行为注入**:
    *   **目标行为**: 被选中的目标被注入随机行为（20% 刹车测试，20% 加速），迫使专家规划器做出反应。
    *   **遮挡注入**: 以 30% 的概率在 Ego 和 Target 之间生成大型车辆（如卡车），以制造部分可观测性。

### 阶段 3：专家控制与审计
*   **专家控制器**: 一个特权 PID/BehaviorAgent 控制器驾驶 Ego 车辆跟随 $v_{target}$ 持续 $T=8.0s$。
    *   *特权*: 专家可以访问目标的真实未来轨迹。
*   **审计器**: 采集完成后，自动化审计脚本会检查：
    *   **安全性**: Ego 与 Target 的距离不得低于 2.0m。
    *   **完整性**: 轨迹长度必须至少达到目标持续时间的 80%。
    *   **一致性**: 最终轨迹必须在几何上与指令一致（例如，“左车道”指令应导致向左的横向位移）。

## 3. 数据集特征

### 3.1 难度分级
为了促进课程学习，我们根据场景的几何模糊性对每个样本进行分级。我们将难度定义为“诱饵”（第二好的候选者）与目标之间的接近程度。

设 $\Delta d = |d_{target} - d_{decoy}|$ 且 $\Delta \theta = |\theta_{target} - \theta_{decoy}|$。

| 等级 | 标准 | 描述 |
| :--- | :--- | :--- |
| **Normal** | $\Delta d \le 2.0m$ | 诱饵在附近，但易于区分。 |
| **Hard** | $\Delta d \le 1.5m, \Delta \theta \le 8^\circ$ | 诱饵非常接近且视觉上相似。 |
| **Ultra** | $\Delta d \le 1.0m, \Delta \theta \le 5^\circ$ | 诱饵几乎重叠（例如：相邻车道切入）。 |

### 3.2 数据结构
每个样本保存为一个压缩的 `.npz` 文件，包含：
*   `graph`: $t=0$ 时刻的静态协议图。
*   `trajectory`: $T$ 步的 Ego 和 Target 位置序列 $(x, y, z, yaw)$。
*   `query`: 自然语言指令字符串。
*   `difficulty`: 计算出的难度等级。
*   `scene_uuid`: 链接反事实对的唯一标识符。

## 4. 在训练中的使用

该数据集支持 **多任务训练策略**：
1.  **选择头**: 使用交叉熵损失在协议图上训练，以根据指令预测正确的目标索引。
2.  **轨迹头**: 使用 MSE 损失训练，以预测所选目标的相对未来轨迹。
3.  **一致性损失**: 一个专门的损失项，如果预测的轨迹偏离了所选目标的未来状态，则进行惩罚。
